# AR-001：Windows 免安装桌面备忘录组件

影响模块：todo-desktop

## 变更意图

### 问题

用户需要一个常驻 Windows 桌面的轻量备忘录，能够快速查看和整理事项，同时在靠近屏幕边缘时减少遮挡。事项必须可靠保存，不能因为默认过滤而丢失。

### 目标

- 提供可拖动、可边缘隐藏/弹出的桌面备忘录窗口。
- 提供背景颜色和“弹出/最小化”快捷键配置。
- 支持事项勾选完成、顺序拖动和未完成/已完成分组不变量。
- 将全部事项和设置持久化到本地；默认隐藏最后活动时间超过 7 天的事项，但可恢复查看。
- 产出无需安装器即可运行的 Windows 自包含发布目录。

### 非目标

- 不做云同步、账号、多设备同步或联网功能。
- 不做提醒通知、重复任务、标签、搜索或自然语言解析。
- 不做系统托盘、自动开机、安装器或卸载器。
- 不把历史过滤误当作删除；本次不提供物理删除事项的业务入口。

### 范围

- 影响模块：todo-desktop
- 边界：Windows 桌面、单用户、本地 JSON 数据、自包含免安装发布。
- 视觉参考：用户附图仅作为深色圆角清单、复选框和完成项中划线的视觉参考，不构成额外文字或交互指令。

## 增量规格

## ADDED Requirements（模块：todo-desktop）

### Requirement: 桌面窗口停靠与弹出

应用必须提供无边框桌面备忘录窗口。窗口可由鼠标拖动；当窗口被拖到任一屏幕边缘时，窗口收拢为可见的窄隐藏点；鼠标移动到隐藏点后恢复窗口。

#### Scenario: 拖动窗口

- **WHEN** 用户在窗口标题区域按住鼠标并移动
- **THEN** 窗口跟随鼠标移动，并在释放后保存新的屏幕位置

#### Scenario: 边缘隐藏

- **WHEN** 用户将窗口拖动到任一工作区边缘并释放
- **THEN** 窗口收拢到该边缘，只保留可命中的隐藏点，不遮挡桌面主要区域
- **AND** 隐藏方向和锚点位置被持久化

#### Scenario: 隐藏点弹出

- **WHEN** 鼠标进入隐藏点
- **THEN** 窗口恢复到隐藏前的位置或对应边缘的可见位置
- **AND** 不创建第二个窗口实例

### Requirement: 外观和快捷键设置

设置界面必须允许用户修改组件背景颜色，以及分别配置弹出和最小化的全局快捷键。配置变更必须立即作用于运行中的窗口并落盘。

#### Scenario: 修改背景颜色

- **WHEN** 用户在设置中选择有效背景颜色并保存
- **THEN** 主窗口立即应用该颜色
- **AND** 重启应用后仍使用该颜色

#### Scenario: 配置快捷键

- **WHEN** 用户为弹出或最小化动作录入未被占用的快捷键并保存
- **THEN** 新快捷键立即生效并覆盖旧快捷键
- **AND** 重启应用后仍使用该快捷键

#### Scenario: 快捷键冲突或无效

- **WHEN** 用户录入空快捷键、格式无效快捷键或与另一个应用动作快捷键冲突的组合
- **THEN** 设置界面拒绝保存并显示明确错误
- **AND** 继续使用上一次有效配置

### Requirement: 事项分组与拖动排序

事项列表必须默认先显示未完成事项，再显示已完成事项。用户可在各自分组内用鼠标拖动排序；任何排序结果都不得让已完成事项出现在未完成事项前面。排序结果必须持久化。

#### Scenario: 默认分组顺序

- **WHEN** 打开或刷新事项列表
- **THEN** 所有显示中的未完成事项位于已完成事项之前
- **AND** 每个分组保留其已保存的相对顺序

#### Scenario: 拖动事项

- **WHEN** 用户拖动事项到同一分组的另一个位置
- **THEN** 事项插入目标位置并保存新的相对顺序
- **AND** 另一个分组的顺序不被改变

#### Scenario: 跨分组拖动约束

- **WHEN** 用户将已完成事项拖到未完成区域，或将未完成事项拖到已完成区域
- **THEN** 系统按当前完成状态将其限制在合法分组位置
- **AND** 已完成事项不得出现在任意未完成事项之前

### Requirement: 勾选完成

每个事项前必须有复选框。用户勾选未完成事项后，该事项变为已完成、文本显示中划线，并自动移动到已完成分组的第一个位置。

#### Scenario: 勾选未完成事项

- **WHEN** 用户选中一个未完成事项的复选框
- **THEN** 事项状态变为已完成
- **AND** 文本显示中划线
- **AND** 事项移动到已完成事项的第一个位置
- **AND** 变更被持久化

#### Scenario: 取消完成

- **WHEN** 用户取消一个已完成事项的复选框
- **THEN** 事项状态变为未完成
- **AND** 事项移动到未完成事项的第一个位置
- **AND** 文本取消中划线并持久化

### Requirement: 本地持久化与历史过滤

系统必须将所有事项和设置持久化到当前用户可写的本地应用数据目录。默认列表只展示最后活动时间在最近 7 天内的事项；超过 7 天的事项仍保存在数据文件中，并可通过“显示历史”恢复展示。

#### Scenario: 重启恢复

- **WHEN** 用户创建、编辑、完成或排序事项后退出并重新打开应用
- **THEN** 事项文本、完成状态、分组顺序和最近活动时间恢复
- **AND** 窗口位置、停靠状态、背景颜色和快捷键恢复

#### Scenario: 默认隐藏旧事项

- **WHEN** 事项的最后活动时间早于当前时间 7 天以上且用户未启用显示历史
- **THEN** 该事项不出现在默认列表中
- **AND** 数据文件中仍保留该事项的完整内容和顺序信息

#### Scenario: 显示历史

- **WHEN** 用户启用“显示历史”
- **THEN** 7 天以前的事项也出现在列表中
- **AND** 仍遵守未完成在前、已完成在后的分组不变量

#### Scenario: 持久化失败

- **WHEN** 数据目录不可写、JSON 损坏或原子替换失败
- **THEN** 应用显示非破坏性错误提示并保留当前内存状态
- **AND** 不用空数据覆盖已有数据

### Requirement: 免安装发布

项目必须提供 Windows 自包含发布方式，用户解压发布目录后直接运行可执行文件，不要求预先安装 .NET Runtime 或安装器。

#### Scenario: 直接启动

- **WHEN** 用户在 Windows 上运行发布目录中的主可执行文件
- **THEN** 应用创建一个可交互的桌面备忘录窗口
- **AND** 核心事项列表可见且可操作
