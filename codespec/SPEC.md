# 全量规格

## 模块：桌面备忘录（todo-desktop）

（AR-001 归档后合并）


### Requirement: 桌面窗口停靠与弹出

应用必须提供无边框桌面备忘录窗口。窗口可由鼠标拖动，也可由鼠标拖动改变大小；当窗口被拖到任一屏幕边缘时，窗口整体移出屏幕（0 像素可见）。**停靠状态会一直保留**：鼠标移动到对应屏幕边缘的原停靠位置时窗口滑出显示，鼠标离开窗口后自动收回；只有把窗口拖离边缘才解除停靠。恢复时必须完整可见。

#### Scenario: 拖动窗口

- **WHEN** 用户在窗口标题区域按住鼠标并移动
- **THEN** 窗口跟随鼠标移动，并在释放后保存新的屏幕位置

#### Scenario: 拖动改变窗口大小

- **WHEN** 用户在窗口边缘或四角（约 6px 感应带）按住鼠标并移动
- **THEN** 窗口跟随鼠标改变宽高，并在接近最小尺寸时停止收缩（不小于 220x160）
- **AND** 松开鼠标后新的位置与尺寸被持久化
- **AND** 隐藏状态下不可改大小

#### Scenario: 边缘隐藏

- **WHEN** 用户将窗口拖动到任一工作区边缘并释放
- **THEN** 窗口整体移出该边缘，屏幕上不再有任何像素可见
- **AND** 保存的恢复位置被夹取到工作区内，保证恢复时完整可见
- **AND** 隐藏方向和锚点位置被持久化

#### Scenario: 边缘弹出与自动收回

- **WHEN** 鼠标移动到停靠边缘，且落在原停靠位置对应的范围内
- **THEN** 窗口滑出恢复到保存的位置并完整可见
- **AND** 停靠状态被保留
- **WHEN** 鼠标随后离开窗口
- **THEN** 窗口自动回到隐藏状态（整体移出屏幕）
- **AND** 再次把鼠标移到该边缘位置可再次滑出
- **AND** 拖动、缩放、事项排序进行中，或设置窗口与删除确认气泡打开时不自动收回
- **AND** 不创建第二个窗口实例

#### Scenario: 解除停靠

- **WHEN** 用户在窗口滑出显示时把它拖离屏幕边缘并释放
- **THEN** 停靠状态被清除
- **AND** 窗口作为普通浮动窗口保留在释放位置

### Requirement: 外观和快捷键设置

设置界面必须允许用户修改组件背景颜色与字体颜色，以及配置**单一的全局快捷键**用于弹出/最小化。背景颜色、字体颜色与不透明度的改动必须**即时预览**在运行中的窗口上，保存后才持久化；取消或关闭设置窗口则回滚。界面字体固定为微软雅黑，不提供字体设置。

#### Scenario: 修改背景颜色

- **WHEN** 用户选择或输入有效的背景颜色
- **THEN** 主窗口立即应用该颜色，无需先保存
- **AND** 保存后重启应用仍使用该颜色；取消则回滚为进入设置前的颜色

#### Scenario: 无背景色

- **WHEN** 用户选择“无背景”（或把背景色输入为 `none`）
- **THEN** 主窗口面板不填充也不描边，只有文字与控件浮在桌面上
- **AND** 行悬停底色与输入框仍按不透明度设置保持可见
- **AND** 设置窗口与删除确认气泡仍使用不透明底色
- **AND** 保存后重启应用仍保持该选择
- **AND** 该选项占用背景预设中的一个色块，预设总数不变

#### Scenario: 修改待办文字颜色

- **WHEN** 用户选择或输入有效的文字颜色
- **THEN** 主窗口的**事项文本**立即改用该颜色，已完成事项使用由它派生的弱化色
- **AND** 标题栏、各类图标、设置窗口与删除确认气泡的颜色**不受影响**（由背景色明暗自动决定）
- **AND** 保存后重启应用仍使用该颜色；取消则回滚为进入设置前的颜色

#### Scenario: 颜色格式无效

- **WHEN** 用户提交的背景颜色或字体颜色不是合法的 `#RRGGBB` 格式
- **THEN** 设置界面拒绝保存并显示明确错误
- **AND** 输入过程中非法的颜色不参与预览，窗口保持当前生效值

#### Scenario: 配置快捷键

- **WHEN** 用户录入一个格式合法且未被占用的全局快捷键并保存
- **THEN** 新快捷键立即生效并覆盖旧快捷键
- **AND** 重启应用后仍使用该快捷键

#### Scenario: 单键切换弹出与最小化

- **WHEN** 用户按下已配置的全局快捷键，且窗口处于边缘隐藏或最小化状态
- **THEN** 窗口被唤出并激活
- **WHEN** 用户按下同一快捷键，且窗口正常显示但不是当前活动窗口（被其他程序盖住）
- **THEN** 窗口被唤到最前并激活，而不是先被收起
- **WHEN** 用户按下同一快捷键，且窗口正常显示且是当前活动窗口
- **THEN** 窗口最小化

#### Scenario: 快捷键无效或被占用

- **WHEN** 用户录入格式无效的快捷键，或该组合已被其他程序占用
- **THEN** 设置界面拒绝保存并显示明确错误
- **AND** 继续使用上一次有效配置

#### Scenario: 留空禁用快捷键

- **WHEN** 用户清空快捷键输入并保存
- **THEN** 全局快捷键被注销，应用不再响应任何全局快捷键

### Requirement: 事项分组与拖动排序

事项列表必须默认先显示未完成事项，再显示已完成事项。用户可在各自分组内用鼠标拖动排序；任何排序结果都不得让已完成事项出现在未完成事项前面。排序结果必须持久化。

#### Scenario: 默认分组顺序

- **WHEN** 打开或刷新事项列表
- **THEN** 所有显示中的未完成事项位于已完成事项之前
- **AND** 每个分组保留其已保存的相对顺序

#### Scenario: 拖动事项

- **WHEN** 用户拖动事项到同一分组的另一个位置
- **THEN** 事项插入目标位置并保存新的相对顺序
- **AND** 另一个分组的顺序不被改变

#### Scenario: 跨分组拖动约束

- **WHEN** 用户将已完成事项拖到未完成区域，或将未完成事项拖到已完成区域
- **THEN** 系统按当前完成状态将其限制在合法分组位置
- **AND** 已完成事项不得出现在任意未完成事项之前

### Requirement: 勾选完成

每个事项前必须有复选框。用户勾选未完成事项后，该事项变为已完成、文本显示中划线，并自动移动到已完成分组的第一个位置。

#### Scenario: 勾选未完成事项

- **WHEN** 用户选中一个未完成事项的复选框
- **THEN** 事项状态变为已完成
- **AND** 文本显示中划线
- **AND** 事项移动到已完成事项的第一个位置
- **AND** 变更被持久化

#### Scenario: 取消完成

- **WHEN** 用户取消一个已完成事项的复选框
- **THEN** 事项状态变为未完成
- **AND** 事项移动到未完成事项的第一个位置
- **AND** 文本取消中划线并持久化

### Requirement: 新建事项

主窗口标题栏必须提供一个加号按钮用于新增事项。点击后在未完成分组的普通区开头（即新事项提交后所在的位置）出现一个已聚焦的内联输入行；提交后新事项插入该位置。

#### Scenario: 内联输入并提交

- **WHEN** 用户点击标题栏的加号按钮
- **THEN** 未完成组普通区开头出现一个已聚焦的输入行，位置就是新事项提交后所在的位置
- **AND** 输入区高度随内容自动增长，可用 Shift+Enter 插入换行
- **AND** 按回车或点击其他区域提交，输入行就地变为正式事项
- **AND** 变更被持久化

#### Scenario: 取消新建

- **WHEN** 用户在输入行按 Esc，或提交空白/纯空格内容
- **THEN** 不创建任何事项，输入行消失

### Requirement: 事项置顶

每个未完成事项必须可以置顶。置顶事项始终显示在未完成分组的最前面，多个置顶事项按置顶的先后顺序排列。置顶事项完成后与普通事项完全一致。已完成事项不可置顶。

#### Scenario: 置顶事项

- **WHEN** 用户点击某未完成事项的置顶按钮
- **THEN** 该事项移动到未完成分组置顶区的末尾（排在已有置顶事项之后）
- **AND** 该行右侧常驻显示强调色图钉标记
- **AND** 变更被持久化

#### Scenario: 取消置顶

- **WHEN** 用户点击已置顶事项的置顶按钮
- **THEN** 该事项回到普通区开头
- **AND** 常驻的图钉标记消失
- **AND** 变更被持久化

#### Scenario: 置顶事项完成与取消完成

- **WHEN** 用户勾选一个已置顶的事项
- **THEN** 该事项进入已完成分组首位，与普通事项一致，置顶状态不影响已完成分组的排序
- **AND** 之后取消完成时，该事项回到未完成分组的置顶区首位

#### Scenario: 已完成事项不可置顶

- **WHEN** 用户尝试对已完成事项执行置顶
- **THEN** 不产生任何置顶效果

#### Scenario: 新建事项与置顶的关系

- **WHEN** 用户新建事项
- **THEN** 新事项插入普通区开头，不会排到置顶事项之前

#### Scenario: 拖动排序与置顶

- **WHEN** 用户拖动置顶事项或普通事项
- **THEN** 置顶事项只能在置顶区内重排，普通事项只能在普通区内重排

### Requirement: 事项编辑与删除

用户必须能够修改已有事项的文本，并能删除不再需要的事项。编辑通过双击事项文本，或点击事项行悬停时出现的编辑图标进入；删除通过点击事项行悬停时出现的删除图标进入，且必须经用户确认后才会真正删除。

#### Scenario: 进入与提交编辑

- **WHEN** 用户双击某事项文本，或点击该行悬停时出现的编辑图标
- **THEN** 该行变为可编辑的多行输入区并获得焦点、全选原文本
- **AND** 输入区高度随内容自动增长：单行文本与普通事项行等高，多行文本完整展开，不需要在单行框里滚动
- **AND** 按回车或点击其他区域提交新文本，按 Shift+Enter 在该位置插入换行，按 Esc 放弃修改并恢复原文本

#### Scenario: 提交空白文本

- **WHEN** 用户在编辑中提交空白或纯空格文本
- **THEN** 编辑被取消，事项保留原文本且不被删除

#### Scenario: 删除前确认

- **WHEN** 用户点击某事项行悬停时出现的删除图标
- **THEN** 在该图标附近出现确认气泡，显示"删除这条事项？"、被删事项的文本摘要，以及取消和删除两个操作
- **AND** 此时不删除任何数据

#### Scenario: 确认删除

- **WHEN** 用户在确认气泡中点击删除
- **THEN** 该事项从列表和数据文件中移除
- **AND** 同组剩余事项的顺序被规范化，另一组的顺序保持不变
- **AND** 变更被持久化

#### Scenario: 取消删除

- **WHEN** 用户在确认气泡中点击取消、按 Esc，或点击气泡外部
- **THEN** 气泡关闭，事项保持不变

### Requirement: 本地持久化与完成事项显示范围

系统必须将所有事项和设置持久化到当前用户可写的本地应用数据目录。主窗口不提供"显示历史"开关。未完成事项始终显示，不参与时间过滤；已完成事项按用户在设置中选择的显示范围过滤：最近一周为最后活动时间在 7 天内，最近一个月为 30 天内，全部为不做时间过滤。等于范围边界的事项仍显示。超出范围的事项仍完整保存在数据文件中，不被删除或修改。

#### Scenario: 重启恢复

- **WHEN** 用户创建、编辑、完成或排序事项后退出并重新打开应用
- **THEN** 事项文本、完成状态、分组顺序和最近活动时间恢复
- **AND** 窗口位置、停靠状态、背景颜色、完成事项显示范围和快捷键恢复

#### Scenario: 未完成事项始终显示

- **WHEN** 某未完成事项的最后活动时间早于当前显示范围的下界
- **THEN** 该事项仍出现在列表中
- **AND** 不因显示范围而被隐藏或删除

#### Scenario: 已完成的旧事项按范围隐藏

- **WHEN** 某已完成事项的最后活动时间早于当前显示范围的下界
- **THEN** 该事项不出现在列表中
- **AND** 数据文件中仍保留该事项的完整内容和顺序信息

#### Scenario: 修改显示范围

- **WHEN** 用户在设置中选择最近一周、最近一个月或全部并保存
- **THEN** 主窗口列表立即按新范围刷新
- **AND** 重启应用后仍使用该范围

#### Scenario: 持久化失败

- **WHEN** 数据目录不可写、JSON 损坏或原子替换失败
- **THEN** 应用显示非破坏性错误提示并保留当前内存状态
- **AND** 不用空数据覆盖已有数据

### Requirement: 窗口置顶与不透明度

主窗口标题栏必须提供一个图钉开关用于把窗口设为始终置顶；设置界面必须允许用户调整主窗口面板的不透明度。置顶切换立即生效并持久化；不透明度在拖动滑块时即时预览、保存后才持久化。

不透明度只影响主窗口面板的底色：桌面可以透过面板显示。面板上的文字、复选框与图标跟随面板不透明度同步变淡，但保留可读下限（面板 100% 时完全不透明；面板降到下限 35% 时约 67% 不透明），既避免文字完全遮挡桌面内容，又维持可读性。设置窗口与删除确认气泡始终使用不透明底色。

#### Scenario: 图钉开关置顶

- **WHEN** 用户点击标题栏的图钉开关
- **THEN** 主窗口立即切换置顶状态，已置顶时图钉以强调色显示
- **AND** 重启应用后仍保持该状态

#### Scenario: 拖动时即时预览不透明度

- **WHEN** 用户拖动不透明度滑块
- **THEN** 主窗口面板底色立即按当前值变为半透明，无需先保存
- **AND** 面板上的文字、复选框与图标随之同步变淡，但不超过可读下限
- **AND** 点击取消或关闭设置窗口时回滚到进入设置前的值，点击保存则持久化该值

#### Scenario: 不透明度越界值

- **WHEN** 状态文件中的不透明度低于 35% 或高于 100%（例如被手工修改）
- **THEN** 读取时被夹取到 35%–100% 区间
- **AND** 不使用会导致窗口不可见的值

### Requirement: 托盘图标与开机自启

主窗口不占用任务栏。应用必须在通知区域提供唯一可见入口，并支持随系统启动。

#### Scenario: 托盘图标与右键菜单

- **WHEN** 应用运行中
- **THEN** 通知区域出现应用图标（可能位于“显示隐藏的图标”折叠区）
- **AND** 右键该图标弹出菜单，包含“显示 / 隐藏”与“退出”
- **AND** 双击图标可切换窗口显示与隐藏

#### Scenario: 从托盘退出

- **WHEN** 用户点击托盘菜单中的“退出”
- **THEN** 应用取消随系统启动（删除当前用户的启动项）
- **AND** 完成一次收尾保存后退出，并移除托盘图标

#### Scenario: 首次运行开启自启动

- **WHEN** 应用首次运行（或状态文件中缺少自启动标记）
- **THEN** 在当前用户的启动项中登记本应用
- **AND** 之后不再自动登记，用户在系统设置里关闭该启动项不会被应用重新打开

### Requirement: 免安装发布

项目必须提供 Windows 自包含发布方式，用户解压发布目录后直接运行可执行文件，不要求预先安装 .NET Runtime 或安装器。

#### Scenario: 直接启动

- **WHEN** 用户在 Windows 上运行发布目录中的主可执行文件
- **THEN** 应用创建一个可交互的桌面备忘录窗口
- **AND** 核心事项列表可见且可操作

#### Scenario: 不占用任务栏

- **WHEN** 应用运行中
- **THEN** 任务栏与 Alt+Tab 切换列表中都不出现该窗口
- **AND** 用户仍可通过全局快捷键唤出窗口

#### Scenario: 带应用图标

- **WHEN** 用户在资源管理器中查看发布目录或桌面快捷方式
- **THEN** 可执行文件显示应用自身的图标，而不是系统默认图标
